# Михаил Борисович — правила работы

## Назначение и контекст
Голосовой ассистент для человека, которому недоступны экран, мышь и клавиатура.
Целевая машина: HP, Celeron N3060, 4 ГБ RAM, Lubuntu; Python/.venv,
Vosk, RHVoice, Firefox/Selenium, PipeWire. Экономить CPU и RAM.
Codex — инструмент разработки, не обязательная часть запущенного ассистента.

Перед задачей прочитай [ROADMAP.md](ROADMAP.md) и [ACCEPTANCE.md](ACCEPTANCE.md),
проверь HEAD, ветку и `git status --short`. Эти документы — навигация, не доказательство:
при расхождении с кодом или локальным diff сначала установи фактическое состояние.

## Границы
- Не использовать OpenAI API, платные API, API keys, внутренние API ChatGPT,
  извлечение cookies/session tokens, скрытое состояние страницы или обход авторизации.
- GPT — через видимый UI обычного Firefox с постоянным отдельным профилем.
  Не подменять его Chromium/Electron, координатами или фиксированным числом Tab.
- Не добавлять тяжёлую локальную LLM. Не исполнять произвольный код из ответа GPT.
- Без отдельного разрешения не менять VPN, ALSA/gain, устройства, системные пакеты,
  Firefox, права Codex, автозапуск/systemd; не делать commit/push/merge/reset/clean.
- Сохранять чужие и незакоммиченные изменения; не закрывать пользовательский Firefox.
  Завершать только проверенно принадлежащие ассистенту процессы.
- Не сохранять сырое аудио, переписку, профили, секреты и дампы в репозиторий.

## Защищаемое поведение
LOCAL_MODE — локальные команды; LARISA_MODE — ChatGPT Voice;
ANTON_MODE — штатная диктовка → текстовый чат → RHVoice, несколько туров.
В GPT-режимах обычные локальные команды запрещены. Возврат требует отдельного
«Михаил Борисович» → «Слушаю» → команды возврата.

Рабочий Stop Антона: заранее установленный DOM-фокус → X11/XTest Space,
с проверками PID, фокуса и единственной подходящей кнопки. При активной диктовке
не добавлять WebDriver-проверки перед этим Stop. Не переисследовать отвергнутые
способы без нового воспроизводимого дефекта.

Недостоверное/устаревшее аудио не разрешает распознавание. Служебные таймеры
продолжают работать. Пропуск кадров сбрасывает незавершённое распознавание.
Не повторять Send автоматически при неизвестном результате отправки.
Не объявлять возврат в LOCAL_MODE до подтверждённого закрытия GPT-сеанса.

## Рабочий цикл и проверки
Одна ограниченная задача → воспроизводящий тест → минимальное исправление →
проверки → короткий отчёт. Не запускать конкурирующих редакторов или несколько
тестовых Firefox. Читать нужные файлы, исключать .venv, модели и большие логи.

Из корня проекта, без sudo:
```bash
git diff --check
.venv/bin/python -m unittest -q
```
Компилировать изменённые и новые Python-файлы через `py_compile`.
При изменении браузерного UI/жизненного цикла запускать последовательно:
```bash
MB_BROWSER_TEST=1 .venv/bin/python -m unittest test_browser_dom -v
```
Тесты зависаний ограничивать внешним timeout и гарантировать очистку.
Использовать fake clock/Event/pipe вместо sleep как доказательства синхронизации.
Различать выполненные/пропущенные тесты, mocks, реальный браузер и живую речь.
Для правок только Markdown не запускать аудио/браузерные тесты без причины.

## Передача результата
Обновлять ROADMAP только при изменении очереди задач, ACCEPTANCE — по доказательствам.
Не переносить старый PASS на новую версию. Неизвестное писать как непроверенное.
В отчёте: изменение, проверки, ограничения, один следующий шаг; без полных дампов.
Перед следующим промптом пользователю указывать отдельно команду выбора модели,
модель и reasoning. Предпочтение пользователя — Standard, без Fast; настройки
не менять молча. Для живого теста дождаться готовности человека, дать одну команду.

AGENTS хранит правила, не историю запусков. Ориентир размера — до 100 строк;
длинные доказательства и старые исследования читать по ссылке при необходимости.
