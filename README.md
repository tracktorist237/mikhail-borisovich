(также «закрой Ларису», «закрой Антона Павловича», «закончи разговор», «стоп»).
Дополнительно **«Михаил вернись»** / **«Михаил Борисович вернись»**
закрывают GPT-сеанс одной фразой, в том числе во время opening. Активный звук
или недостоверный speaker monitor по-прежнему блокируют распознавание.
Одиночные «Михаил» и «Вернись» не стали глобальными командами закрытия.
При двухшаговом возврате перед «Слушаю» микрофон Voice выключается либо
диктовка останавливается без Send и composer очищается.
Возврат закрывает только Firefox GPT-сеанса, говорит «Я снова слушаю.» и
возвращает LOCAL_MODE/WAITING. Если завершение не удалось, локальные команды
остаются заблокированы. Ctrl+C завершает приложение и его браузерный сеанс.

## Firefox и звук

Зависимости Python устанавливаются из `requirements.txt`. Системные программы:
Firefox, geckodriver, PipeWire (`pw-record`, `pw-play`), RHVoice-test.
Пути Firefox и geckodriver задаются в `config.json`; текущие значения для Snap.
Постоянный профиль: `~/snap/firefox/common/mb-profile`.
Профиль используется непосредственно через `-profile`, не клонируется.
Не открывайте этот же профиль одновременно в другом процессе Firefox.
Обычный пользовательский Firefox может оставаться открытым, но на 4 ГБ RAM
это заметно увеличивает нагрузку. Автоматически его окна не закрываются.

Вход в Plus и разрешение микрофона уже выданы пользователем и сохранены.
Для первоначальной настройки на другой машине: `firefox_probe.py --setup`.
Диагностика ждёт интерактивный composer, а не первые кнопки SSR-оболочки.
Автоматизация не обходит новые запросы разрешений, логин или CAPTCHA.

`speaker_activity.py` читает PCM monitor текущего default sink через
`pw-record`, 8000 Гц, stereo s16. На диск звук не записывается. Полные оба
канала исключают ложную тишину при противофазе. Начальные пороги: RMS 100,
peak 1000 (шкала int16); разрешение распознавания после 800 мс тишины.
Настройки: `speaker_rms`, `speaker_peak`, `speaker_silence_ms`.
Состояния: `[SPEAKER ACTIVE] rms=...`, `[SPEAKER SILENT] rms=...`.
`SPEAKER UNAVAILABLE` означает задержку/недоступность мониторинга, а не звук.
При этом распознавание блокируется. Аудиоблоки старше 400 мс отбрасываются.
RHVoice дополнительно блокирует распознавание на всё время синтеза,
воспроизведения и последующей паузы. Это не акустическое эхоподавление.

Настройки диктовки: `dictation_rms` (уровень микрофона),
`dictation_silence_ms` (1400 мс паузы), `dictation_max_seconds` (45 с),
`reply_timeout` (180 с). Начинайте вопрос после начала записи на странице;
после загрузки браузера может понадобиться заметная пауза. Порог микрофона
нужно проверить с реальным голосом пользователя.

## Проверки и замеры

```sh
.venv/bin/python -m unittest -q
.venv/bin/python test_mvp.py --recognition
.venv/bin/python test_mvp.py --recognition-chatgpt
.venv/bin/python main.py --run-seconds 30
.venv/bin/python main.py --check-mode larisa --run-seconds 120
.venv/bin/python main.py --check-mode anton --run-seconds 120
.venv/bin/python measure_resources.py --pid PID --seconds 20 --label MODE
```

`--check-mode` — диагностический вход без wake word, не acceptance A/B.
`measure_resources.py` измеряет CPU и RSS дерева выбранного процесса.
100% CPU означает одно полностью занятое ядро. Сумма RSS повторно учитывает
общие страницы; это не PSS. Короткоживущие процессы между отсчётами могут
не попасть в замер. Также выводятся максимум числа процессов Firefox в этом
дереве и системные максимумы занятого обычного swap, логических данных zram
и физической RAM zram. Метрики `system_*` относятся ко всей системе, не только
к измеряемому приложению. При выходе корневого процесса замер отклоняется как
неполный. Финальный benchmark четырёх режимов выполняется после acceptance.
Systemd и автозапуск не добавлены.

## Ручной запуск

В терминале пользовательской графической сессии, без sudo:

```bash
cd ~/mikhail-borisovich
.venv/bin/python diagnose.py
.venv/bin/python main.py
```

После голосового сообщения о готовности скажите «Михаил» или «Михаил Борисович». Дождитесь окончания «Слушаю», затем произнесите одну команду. У этого wake-ответа дополнительная фиксированная пауза убрана; узкий live smoke immediate TIME принят 29.09 (6/6), без гарантии для всех условий. После ответа ассистент снова ждёт обращения. После неизвестной команды он говорит «Не понял. Повторите команду.» и даёт ещё одну попытку без обращения. После второй неудачи: «Не понял. Возвращаюсь в режим ожидания.» Если команда не поступила за 12 секунд, ожидание обращения возобновляется. Экран, мышь и клавиатура в этом цикле не нужны. Первоначальный ручной запуск выполняет помощник; автозапуск пока не настроен.

| Команда | Действие |
|---|---|
| который час / сколько времени / время / час | Системное местное время |
| какая дата / какое сегодня число / сегодняшняя дата / дата | Текущая дата |
| громче / сделай громче / прибавь звук; тише / сделай тише / убавь звук | Изменить громкость на 10 процентных пунктов |
| громкость N процентов | От 0 до 100, число произносится словами |
| открой Firefox / открой браузер | Запустить Firefox |
| закрой Firefox / закрой браузер | Послать SIGTERM процессам Firefox текущего пользователя |
| есть интернет / интернет / проверь интернет / есть связь | Проверить возможность TCP подключения к публичным адресам |
| какой заряд / сколько заряда / батарея / заряд | Заряд и состояние батареи из Linux sysfs |
| повтори | Повторить последний содержательный ответ |
| стоп / замолчи / хватит | Отменить ожидание команды |

Во время синтеза, воспроизведения и защитной паузы распознавание отключено. «Стоп», «замолчи» и «хватит» работают в LISTENING и возвращают к ожиданию «Михаил». Перебивание TTS отключено для защиты от собственного голоса. При громкости 0 ответы неслышны; голосовая команда «Михаил», пауза около двух секунд, «громче» восстанавливает звук. Остановка процесса обслуживающим человеком — Ctrl+C.

## Настройки

`config.json`: `voice: "auto"` выбирает русский мужской Mikhail, иначе первый установленный русский мужской голос. Можно указать имя из диагностики. `input_device: null` использует системный микрофон; можно задать номер или уникальную часть названия. `volume_step` — шаг громкости, `command_timeout` — время ожидания. `sample_rate` — 16000 Гц. `tts_cooldown_ms: 500` — пауза после TTS в миллисекундах (допустимо 300–2000; при заметном эхе попробуйте 700). Для обычных ответов и retry cooldown и очистка сохранены. Wake-ответ «Слушаю» использует отдельную границу завершения playback в часах PortAudio: TTS/пересекающие границу блоки запрещены, свежие пользовательские блоки сохраняются. Очередь остаётся ограниченной, защита от устаревшего аудио включена.

`silence_rms: 100` — порог пропуска тишины (16-битный PCM). При тихой речи уменьшите его, например до 50; если постоянный шум включает распознавание, увеличьте. В тишине Vosk не получает кадры; проверяется энергия каждого блока по 100 мс. Буфер предыдущих 300 мс сохраняет начало обращения. После звука обрабатывается ещё 1,2 секунды. В ожидании используется словарь из двух обращений и неизвестной речи; для команд — ограниченная грамматика. Одна маленькая модель общая для двух распознавателей. Очередь аудио ограничена.

В словаре модели нет цельного слова Firefox: грамматика использует «файр фокс» и «фаер фокс», которые преобразуются в Firefox. Основные варианты — «открой браузер» и «закрой браузер»; обратный порядок тоже поддерживается. После отдельного «открой» или «закрой» на повторной попытке можно сказать только «firefox»/«браузер». Без этого контекста название браузера не выполняет действие. Сопоставление учитывает границы слов, допускает посторонние слова вокруг фразы; «пять firefox» и «открой час» не выполняются. «Процент замолчи» означает STOP, громкость не меняет.

## Диагностика и проверки

```bash
.venv/bin/python diagnose.py --voices
.venv/bin/python diagnose.py --devices
.venv/bin/python diagnose.py
.venv/bin/python main.py --run-seconds 30
.venv/bin/python test_mvp.py
.venv/bin/python test_mvp.py --recognition
```

Диагностика записывает две секунды с микрофона, сообщает уровень сигнала, проверяет аудиовыход, синтезирует и проигрывает фразу RHVoice, загружает модель и проверяет интернет. Отсутствие интернета не мешает работе. Код завершения 1 означает ошибку локального компонента. Последний тест синтезирует команды в WAV и реально распознаёт их Vosk; это не заменяет проверку человеческой речи через микрофон.

Логи: `[WAITING]`, `[WAKE WORD]`, `[LISTENING]`, `[COMMAND]`, `[SPEAKING]`, `[ERROR]`. При отсутствии микрофона или синтеза выводится понятная ошибка без traceback. В песочнице аудиоустройства могут быть скрыты: запускать нужно в обычной пользовательской сессии Lubuntu. PortAudio использует установленную системную библиотеку `libportaudio2`; RHVoice и его русский голос должны быть установлены.

## Offline Loop Replay (Phase 1)

Для отдельного ASR-прогона и подготовки внешнего corpus:

```bash
.venv/bin/python audio_replay.py --corpus ~/mb-test-audio --mode asr
# Только отдельная согласованная запись с физическим микрофоном/RHVoice:
.venv/bin/python record_test_corpus.py --corpus ~/mb-test-audio --resume
```

Recorder ничего не переобучает и не перезаписывает готовые takes. ASR использует
настоящий Vosk без микрофона, но не проверяет state machine. Loop ниже проверяет
её с fake внешней средой. Пользовательские WAV/manifest остаются вне Git.

```bash
.venv/bin/python loop_replay.py --corpus ~/mb-test-audio \
  --scenarios ~/mb-test-audio/loop-scenarios.json
.venv/bin/python loop_replay.py --corpus ~/mb-test-audio \
  --scenarios ~/mb-test-audio/loop-scenarios.json --scenario anton-atomic-pending \
  --report ~/mb-test-audio/reports/loop-next.json
```

Сценарии — отдельный внешний JSON; шаблон: [examples/loop-scenarios.json](examples/loop-scenarios.json).
Также доступны `--tag` и `--verbose`. Report создаётся только по запросу, вне Git,
в новый файл. WAV/manifest не переписываются. Используется локальная модель Vosk,
production loop и реальные grammar; микрофон, RHVoice, Firefox, сеть и системные
действия заменены fake-зависимостями. Неизвестное действие — FAIL.

`steps[].at` привязывает запись к наблюдаемому событию, `offset_ms` задаёт смещение.
`align: clip_start` сохраняет всю исходную тишину и НЕ доказывает speech onset=0.
`align: speech_onset` требует `speech_onset_frame` из manifest либо внешнее поле
`annotations: {"clip-id": {"speech_onset_frame": 1600, "verified": true}}`.
Это разметка ground truth, не автоматическая RMS-догадка. Без неё — NOT RUN.
`timing` отдельно задаёт callback delay и main-loop delay; события `main_delay`,
`gap`, `guard`, `callback_delay` управляют средой, без Python/shell из JSON.
`bridge` задаёт ограниченные action → delay/result; `expected` остаётся независимым эталоном.

Виртуальный wake/control cue по умолчанию длится 6 секунд, чтобы полный WAV
wake с исходной тишиной успел закончиться; это НЕ измерение RHVoice latency.
Обычный fake-ответ длится 0,3 с после 0,1 с synthesis. Таймауты production,
400-мс freshness и очередь из 12 блоков не меняются. Неподходящие перекрытия
полных записей дают FAIL; скрытого trim/mixing нет. `stop_at: mode.…` завершает
сценарий в точке наблюдения с выполнением настоящего `listen.finally`.

Исходный real-voice набор: 16 PASS / 0 FAIL / 4 NOT RUN; с новой matrix —
51 PASS / 0 FAIL / 4 NOT RUN, 38/38 WAV coverage (см. ACCEPTANCE).
`--debug-trace` добавляет в report provenance блоков и поколения ASR, без PCM.
CLI возвращает nonzero при обязательном FAIL/NOT RUN; пример не обещает все PASS.
Loop replay не заменяет живую проверку акустического эха, устройств, browser
permissions, сети, ChatGPT Voice и задержек целевого ноутбука.


### Расширенное offline coverage и диагностика wake

```bash
.venv/bin/python loop_replay.py --corpus ~/mb-test-audio --matrix all
.venv/bin/python suggest_onsets.py --corpus ~/mb-test-audio \
  --report ~/mb-test-audio/reports/onset-next.json
.venv/bin/python wake_perf.py --count 20 \
  --report ~/mb-test-audio/reports/wake-perf-next.json
```

`--matrix all` можно объединить с `--scenarios`: исходные сценарии сохраняются,
добавляются templates для всех supported WAV. Expected берётся из manifest,
не из matcher. Полные записи не обрезаются; проверяются ровно один wake/intent,
точные количества управляющих действий и минимум 2 с наблюдения после последнего
input/значимого результата. Штатный периодический poll не считается duplicate.
Report показывает фактически доставленные clips и отдельно matrix summary.

Onset suggestions — только RMS-кандидаты, `verified=false`; WAV/manifest не
меняются, NOT RUN автоматически не снимается. Offline wake-perf загружает Model
один раз, измеряет создание backend и первый AcceptWaveform на искусственной
тишине. Это не live responsiveness и не проверка акустического эха.

Только для согласованного живого smoke: `wake_perf.py --live` запускает обычный
`main.main()` с временной обёрткой FreshWake factory и `[WAKE PERF]` числами.
Ctrl+C обрабатывается приложением. Без этого явного launcher диагностика отключена;
в ней нет PCM/распознанного текста. Обычные LOCAL ASR логи приложения сохраняются.
