# План — Михаил Борисович

Цель: после первоначальной настройки пользователь управляет ассистентом голосом.
Михаил выполняет локальные команды, Лариса разговаривает через Voice, Антон
принимает диктовку в текстовый ChatGPT и читает ответ. Далее — проверяемое
выполнение многошаговых просьб с помощью GPT, не запуск произвольного shell-кода.

Основания и ограничения — в [ACCEPTANCE.md](ACCEPTANCE.md).

## Сейчас: блокер SIGINT / pipeline cleanup
Ограниченное закрытие `Bridge.close()` реализовано и проверено локально:
отдельный UI-worker и независимый supervisor, общий бюджет 12 секунд,
подтверждение завершения принадлежащих сеансу процессов. Подробности —
[BROWSER-SHUTDOWN.md](BROWSER-SHUTDOWN.md); повторно реализовывать закрытие не нужно.

Живой запуск через обычный `tee` подтвердил рабочую цепочку Антона, но финальная
очистка после Ctrl+C не прошла. Воспроизведён обрыв cleanup из-за BrokenPipeError
при диагностическом выводе; внесено минимальное исправление без смены архитектуры.
Текущая задача — закрыть этот блокер доказательствами: автоматические результаты
и границы записаны в ACCEPTANCE; живой повтор выхода через `tee` после исправления
ещё не выполнен и требует отдельной готовности пользователя.

Готово, когда Ctrl+C подтверждённо завершает собственное дерево процессов,
сохраняя чужой Firefox. Причины отдельных UI TypeError/RuntimeError пока неизвестны.
Benchmark, Agent Mode, автозапуск
и настройка звука не входят в текущую задачу.

## Не блокировать друг другом
Подключение внешнего микрофона и колонок — отдельная аппаратная задача.
Оно нужно для итоговой оценки качества речи, но не для тестов очередей/процессов.
Причины задержек устанавливать измерением, не объявлять CPU или gain единственной
причиной по одному симптому. Не ждать идеального звука для проектирования агента;
зависания, случайные действия и повторные отправки остаются блокерами выпуска.

## Рабочий ритм
Один проход → тесты → ревью → нужная живая проверка → разрешённый checkpoint.
После доказанного результата закрывать этап; не оптимизировать без измеримого дефекта.
Не повторять старый benchmark: использовать `measure_resources.py`, время ответа
измерять отдельно. Передавать модели сводку и относящийся к ошибке фрагмент лога.

## Обновление

Результаты запусков — только в ACCEPTANCE. Большую историю не копировать.
