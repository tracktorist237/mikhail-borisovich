# План — Михаил Борисович

Цель: после первоначальной настройки пользователь управляет ассистентом голосом.
Михаил выполняет локальные команды, Лариса разговаривает через Voice, Антон
принимает диктовку в текстовый ChatGPT и читает ответ. Далее — проверяемое
выполнение многошаговых просьб с помощью GPT, не запуск произвольного shell-кода.

## Основания WIP и предшествующие проверки
Полный живой regression на HEAD `4026c44c5b11f952811925a6087bb6408b284599`
пройден: LOCAL_MODE, два вопроса Антону с RHVoice, возврат, разговор с Ларисой
и возврат, затем Ctrl+C через обычный `tee` с очисткой принадлежащих браузерных
процессов. Подробности и границы результата — в [ACCEPTANCE.md](ACCEPTANCE.md).

После review усилена граница локального wake-ответа: завершение плеера отмечается
одноразовым wait/event независимо от позднего poll главного цикла; PCM сравнивается
с этой границей по времени захвата PortAudio, а не доставки callback. Поздние TTS
и пересекающие границу блоки отбрасываются; полностью свежие не удаляются очисткой
очереди. Дополнительных 500 мс у wake-ответа нет, обычный/retry cooldown сохранён.
Это АВТО, не живой PASS; задержка планирования waiter и акустический хвост ещё
требуют проверки на машине. GPTModes в этом проходе не менялся. Склонение времени
и исправление батареи сохранены.

Последующий `live-final-20260923-191334.log` не закрыл immediate readiness:
первая команда времени прошла, следующая потребовала retry, после возврата
команда не была услышана. У каждого локального wake отмечен overflow=2.
Это был воспроизведённый дефект потери первых LOCAL блоков около speaking → listening.
Автоматически воспроизведён отказ от чтения очереди на протяжении wake-TTS,
затем устаревание пользовательского блока за очередью старого PCM. Теперь
просроченный префикс убирается и во время ожидания, а на переходе старый TTS
удаляется одним ограниченным проходом. Размер 12 и свежесть 400 мс сохранены.
Добавлена одна сводка LOCAL READY на переход. Полное исправление живого UX
не объявлено: конкретные задержки CPU/cleanup в том логе не измерялись.

Последующий live-ready выявил нестабильность старта Ларисы: два внешних timeout

## Архив плана regression перед новым Loop Replay WIP

Это прежний план, частично выполненный 24.09. Он не добавляет ещё один обязательный
live-набор к уже принятому LOCAL smoke. При следующем release выбирать относящиеся к
изменениям проверки по [COVERAGE.md](COVERAGE.md).

Control replay использует production-классификацию. На внешнем corpus сначала
получено 35 supported PASS / 0 FAIL и 3 planned; после реализации atomic return
и явного обновления ожиданий трёх cases — 38 supported PASS / 0 FAIL.
WAV не менялись. Это ASR-проверка записей, не loop replay и не live acceptance.

Добавлен GPT-only возврат «Михаил вернись» / «Михаил Борисович вернись»:
не ждёт pending open/Send, использует существующий bounded cleanup. Самостоятельные
«Михаил» и «Вернись» не стали глобальными командами. Двухшаговый возврат сохранён;
control wake теперь ждёт final Vosk, чтобы partial-префикс не обрывал длинную atomic
фразу. Во время TTS/активного выхода/недостоверного monitor распознавание запрещено.
АВТО не подтверждает удобство endpoint-задержки на реальной машине.

Прежний план короткой серии (не текущее поручение пользователю):

1. LOCAL: три команды сразу после «Слушаю», без намеренной паузы; сохранить final/intent.
2. Atomic cancel: отдельно «Позови Антона Павловича» и «Позови Ларису»;
   во время opening сказать «Михаил вернись». Дождаться owned descendants reaped
   и LOCAL_MODE; новый вход только после завершения очистки.
3. Лариса: несколько полных startup до реального голосового ответа; проверить
   microphone-control → microphone-click (если нужен) → microphone-active,
   затем PipeWire. Старый mic FAIL не становится live PASS от АВТО.
4. Обычный двухшаговый возврат: «Михаил Борисович» → «Слушаю» → «Вернись».

LOCAL queue/stale/playback policy в этом проходе не менялась. Исправления
Bridge/SIGINT остаются закрытыми. Новый live PASS atomic и обеих веток mic readiness
получен по подтверждению пользователя 24.09; голосовой ответ в этих mic-runs
не подтверждён. Повторный короткий regression проверяет воспроизводимость.

Исторический полный unit-прогон имел один ошибочный process test с тестовым
budget 3 с. Подробный разбор этапа supervisor exit, изменение только test fixture
на production 12 с, повторные проверки и свежий полный результат — в ACCEPTANCE.
Production budgets и архитектура Bridge/SIGINT не меняются.

## Не блокировать друг другом
Подключение внешнего микрофона и колонок — отдельная аппаратная задача.
Оно нужно для итоговой оценки качества речи, но не для тестов очередей/процессов.
Причины задержек устанавливать измерением, не объявлять CPU или gain единственной
причиной по одному симптому. Не ждать идеального звука для проектирования агента;
зависания, случайные действия и повторные отправки остаются блокерами выпуска.

## Рабочий ритм
Один проход → тесты → ревью → нужная живая проверка → разрешённый checkpoint.
После доказанного результата закрывать этап; не оптимизировать без измеримого дефекта.
Не повторять старый benchmark: использовать `measure_resources.py`, время ответа
измерять отдельно. Передавать модели сводку и относящийся к ошибке фрагмент лога.
