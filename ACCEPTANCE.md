Подтверждённая причина: ошибка вывода могла прервать `_close_locked()` до создания
запроса закрытия, а в supervisor — `begin_close()`/диагностику перед terminate/reap.

такое же прерывание `_retire()` OutputGuard. Теперь сообщения очистки best-effort;
обнаруженная в фоновом потоке потеря вывода сообщает основному циклу о необходимости
выхода. Обработчики сигналов не выполняют cleanup; Ctrl+C не подавлен в приложении.
Существующие сессия supervisor и бюджет 12 секунд сохранены (в fixtures — 3 секунды).

Гипотеза прямого SIGINT supervisor/worker не подтвердилась: тест проверяет их
отдельную сессию/группу. В fixture выход из аудиоконтекста состоялся до cleanup;
задержка реального PortAudio в живом сбое не измерена и причиной не объявляется.
Тесты подтверждают выход приложения, controller-thread и всех собственных потомков,
включая SIGTERM-resistant и зомби; посторонний контрольный процесс остаётся жив.
В зависшем Send результат неизвестен, повторной отправки нет.

Исторические процессы сначала сверены по актуальным PID/PPID/PGID/SID/TPGID,

## UX LOCAL_MODE и склонение времени — АВТО, 22.09.2026
Версия: незакоммиченные изменения поверх HEAD `4026c44c5b11f952811925a6087bb6408b284599`.
Перед изменениями сохранены main/test_mvp и уже изменённые документы в
`~/mb-source-backups/20260922-230824-local-ready`.

Причина задержки: после `Speech.busy() == False` локальный цикл всегда ждал
`tts_cooldown_ms` (500 мс), очищая очередь на входе в cooldown и перед listening.
Для wake-ответа добавлена явная политика `playback_end`: граница `accept_after`
фиксируется при подтверждённом завершении playback, затем один сброс recognizer
и переход к listening без очистки очереди. Кадры с временем не позже границы
отбрасываются; первый свежий кадр, в том числе пришедший во время Reset, сохраняется.
Для остальных TTS, включая retry, прежний cooldown и очистка сохранены.
Speech, GPTModes, speaker monitor, config и браузерный код не менялись.

свежего блока при переходе; также подтверждён старый ответ «22 часов 1 минут».

ошибок 0, пропущено 0. Проверены отсутствие дополнительного ожидания после
подтверждения playback, сохранение первого слова, отбрасывание кадров playback,
обычный cooldown/retry, отличие конца синтеза от конца playback и склонение.
`ru_form` проверен для часов и минут на 1, 2, 5, 11, 21, 22, 25; ответ TIME
использует этот helper. Существующий тест retry моделирует один wake-вызов и
сохраняет проверку отбрасывания эха обычных ответов.

[Единственный полный unit-прогон](logs/unit-local-ready-final.log): обнаружено 98,
выполнено 93, успешно 93, ошибок 0; пропущено 5 opt-in browser-тестов.

интервала. Поздний callback не меняет время capture. Блок до границы или
пересекающий её отбрасывается целиком, недостоверный тоже. Полностью последующий

поведение под нагрузкой пока не проверены живым тестом; обещания абсолютного
сохранения первого слога при любой перегрузке нет. Пересекающий границу 100-мс

### Process test: бюджет, стадия и неопределённость
Исторически ошибся один тест:
`test_bridge_shutdown.ShutdownTests.test_hung_job_kills_and_reaps_owned_tree_only`.
Две записи error относятся к нему и его cleanup: общий deadline истёк, затем
`Browser supervisor exit not confirmed within budget`. Это стадия подтверждения
выхода supervisor после ACK о сборе потомков; ACK сам по себе недостаточен.
В историческом полном логе нет временных меток, поэтому распределение затрат
того запуска и конкретная причина задержки scheduler/exit **не установлены**.
Production race не воспроизведён и не объявляется исключённым для всех условий.

Расчёт существующего алгоритма при бюджете B: normal до 0,5B, TERM до 0,7B,
затем KILL/reap/IPC/выход supervisor/join controller должны уложиться в оставшиеся
0,3B; около конца есть резерв 0,1 с для сообщения об ошибке. При B=3 с kill начинается
около 2,1 с, хвост меньше 0,9 с. При production B=12 с — около 8,4 с и хвост меньше
3,6 с. Poll IPC — 20 мс, flush — до 10 мс за итерацию; длительного скрытого sleep
нет. Верхний предел успешного close — общий B, а не сумма новых таймаутов.
Не существует конечной гарантии задержки OS scheduling/непрерываемой D-задачи:
при исчерпании B cleanup остаётся неподтверждённым, LOCAL/new session запрещены.

Новый тест с виртуальными часами воспроизводит именно недостаток остаточного
бюджета: ACK на 0,7B+20 мс и задержка supervisor exit 1 с дают отказ при B=3,
успех при B=12. Это контролируемая модель, **не измерение исторической задержки**.
Отдельный реальный supervisor удерживается pipe после reap ACK: Future ещё pending,
новый сеанс заблокирован; только после разрешения выхода подтверждаются close,
выход controller и отсутствие потомков. Синхронизация без случайного sleep.

Изменение fixture: только упавший интеграционный тест использует существующий
production budget `Bridge().budget` = **12 с**, вместо искусственных 3 с.
Production deadline не изменён; короткий fail-closed сценарий сохранён отдельно.
Пять последовательных повторов прошли: 9,669 / 9,466 / 9,660 / 9,462 / 9,542 с
на целый тест, с собственной очисткой и внешним timeout. Все пять: без оставшихся
процессов; реальная зависшая UI-задача и SIGTERM-resistant дерево завершаются.
