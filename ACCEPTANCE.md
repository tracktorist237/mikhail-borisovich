## SIGINT / потеря вывода: воспроизведение и границы
Повторная проверка 22.09 без изменений исходников:
[точечный прогон](logs/sigint-recheck-targeted.log) — выполнено 7, успешно 7,
ошибок 0, пропущено 0; [один полный unit-прогон](logs/unit-sigint-recheck.log) —
обнаружено 92, выполнено 87, успешно 87, ошибок 0, пропущено 5 браузерных.
`git diff --check` и `py_compile` шести Python-файлов исправления прошли.
[Хеши исходников](logs/sigint-recheck-source-hashes.log) связывают повтор с кодом.
Браузерный набор заново не запускался: код не менялся; его результат 21.09
в таблице выше относится к предыдущему запуску. Живой повтор не выполнялся.
[Новый снимок процессов](logs/sigint-recheck-processes.log) и
[окна](logs/sigint-recheck-windows.log): исторические PID 15899/18467/18525
отсутствуют; текущее окно Firefox принадлежит PID 2609. В этом проходе
существующие браузерные процессы не завершались.

Источник: АВТО, `test_sigint_shutdown`, реальные дочерние процессы и управляющий
PTY с foreground process group; Ctrl+C передаётся байтом `\x03` терминальному драйверу.
Выполняется настоящий `main.main()`/`listen()` с подставными аудио/Vosk/RHVoice/UI;
Bridge, supervisor, worker и потомки реальные. Это не проверка физического аудио.

| Условие | До исправления | После исправления |
|---|---|---|
| Ctrl+C без pipeline / вывод в файл | PASS / PASS | PASS / PASS |
| Ctrl+C через обычный tee | FAIL, BrokenPipeError, потомки остались | PASS, приложение и дерево завершены |
| Ctrl+C через tee -i | PASS, диагностический контроль | PASS; не является исправлением приложения |
| Закрытый stdout/stderr | FAIL, cleanup прерван | PASS |
| EOF родительского IPC и закрытый вывод | FAIL, supervisor вышел с кодом 120 | PASS, самостоятельный terminate → kill → reap |
| Потеря stderr в фоновом потоке | Отдельно не запускалось | PASS, основной цикл выходит и выполняет cleanup |

Логи: [до исправления](logs/sigint-before.log),
[точечные дефекты диагностики и EOF](logs/sigint-diagnostic-before.log),
[после исправления](logs/sigint-after.log): 7 тестов выполнено, 7 успешно,
ошибок 0, пропусков 0; тест терминального SIGINT включает четыре варианта запуска.
Они также входят в полный unit-набор, не прибавлять их как уникальные тесты.

Подтверждённая причина: ошибка вывода могла прервать `_close_locked()` до создания
запроса закрытия, а в supervisor — `begin_close()`/диагностику перед terminate/reap.
При EOF supervisor тоже печатал в уже закрытый pipe. Отдельный тест воспроизвёл
такое же прерывание `_retire()` OutputGuard. Теперь сообщения очистки best-effort;
обнаруженная в фоновом потоке потеря вывода сообщает основному циклу о необходимости
выхода. Обработчики сигналов не выполняют cleanup; Ctrl+C не подавлен в приложении.
Существующие сессия supervisor и бюджет 12 секунд сохранены (в fixtures — 3 секунды).

Гипотеза прямого SIGINT supervisor/worker не подтвердилась: тест проверяет их
отдельную сессию/группу. В fixture выход из аудиоконтекста состоялся до cleanup;
задержка реального PortAudio в живом сбое не измерена и причиной не объявляется.
Тесты подтверждают выход приложения, controller-thread и всех собственных потомков,
включая SIGTERM-resistant и зомби; посторонний контрольный процесс остаётся жив.
В зависшем Send результат неизвестен, повторной отправки нет.

Исторические процессы сначала сверены по актуальным PID/PPID/PGID/SID/TPGID,
состоянию и времени запуска: [снимок](logs/sigint-process-before.log),
[окна](logs/sigint-window-before.log), [владение](logs/sigint-historical-ownership.log).
Geckodriver 18467 из каталога проекта и его единственный потомок-зомби 18525
завершены и собраны после проверки идентичности через pidfd; [результат](logs/sigint-historical-cleanup.log)
подтверждает отсутствие обоих. Видимое окно принадлежит пользовательскому Firefox
15899, запущенному через файловый менеджер: процесс сохранён. Зомби не записывает звук.
После браузерного набора [итоговая проверка](logs/sigint-final-cleanup.log)
не нашла Firefox с тестовыми профилями; исторических остатков тоже нет,
пользовательский Firefox сохранён. В браузерном наборе остался прежний некритический
`ResourceWarning` об очистке `HTTPError 405`; он не исследовался в этой задаче.

Причины живых TypeError/RuntimeError неизвестны: старый лог содержит только тип.
Добавлен локальный `logs/browser-errors.log`: action, тип, общее безопасное описание
и traceback с файлами/строками/именами функций; без текста исключения, исходных строк,
локальных переменных и переписки. Проверена редактированная диагностика подставных
ошибок; сами живые исключения не воспроизведены и не приписываются фокусу окна.

## Следующие проверки
После разрешения пользователя — прежде всего повторный живой Ctrl+C через обычный
tee с подтверждением очистки. Затем общий живой регрессионный сценарий:
1. Запуск → «Михаил» → время.
2. Антон: два вопроса, два ответа RHVoice, очередная диктовка.
3. «Михаил Борисович» → «Слушаю» → «Вернись» → локальная команда.
4. Лариса: настоящий голосовой ответ, возврат, локальная команда.
5. Выход приложения: его процессы завершены, чужой Firefox сохранён.

Для выпуска: несколько повторов, 30–60 минут работы, проверка неисправностей,
CPU/RAM/zram и задержек при фиксированных условиях. Не начинать неожиданный
отсчёт речи: сначала дать команду и дождаться готовности человека.
Модульный тест, синтетический WAV и локальная HTML-страница не заменяют живой тест.
