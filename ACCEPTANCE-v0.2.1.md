# v0.2.1 — рабочая ветка, acceptance не завершён

Ветка `feature/chatgpt-voice`, база `71a31f3`, стабильная локальная версия
`b1cc85d`. Текущие правки v0.2.1 не коммитятся автоматически. Systemd и
автозапуск не добавлены.

## Реализовано в коде

- Существующий локальный цикл Vosk/RHVoice сохранён. Добавлены все варианты
  LARISA_OPEN и ANTON_OPEN; старые CHATGPT_OPEN/CLOSE сохранены.
- Изолированная машина LOCAL_MODE / LARISA_MODE / ANTON_MODE. Во время
  открытия браузера и во всех GPT-фазах обычные локальные команды отключены.
- Firefox/Selenium, отдельный постоянный профиль
  `/home/sergey/snap/firefox/common/mb-profile`. Профиль используется
  непосредственно, не клонируется. Вход Plus и permission микрофона сохранены.
- Лариса: объявление, ожидание окончания RHVoice/эха, Start Voice,
  подтверждение End Voice + Turn off microphone + входного аудиопотока Firefox.
  Это подтверждает UI/микрофон, но не завершённый разговор с сервером.
- Антон: запуск штатной диктовки, VAD по RMS микрофона (production
  `dictation_rms=1000`), остановка после паузы
  через подтверждённый os-keyboard Stop,
  ожидание непустого composer/Send, отправка, новый завершённый ответ через DOM,
  RHVoice частями, следующий тур. Stop подтверждён на реальном ChatGPT:
  DOM заранее фокусирует единственную видимую кнопку, X11/XTest отправляет
  Space только активному окну принадлежащего Firefox, после чего видны
  Transcribing, непустой composer и активный Send.
- Возврат: полное обращение «Михаил Борисович», выключение микрофона Voice
  либо отмена диктовки, «Слушаю», команда возврата, закрытие собственного
  Firefox, «Я снова слушаю.», LOCAL_MODE/WAITING. При неподтверждённом закрытии
  локальные действия заблокированы. Это проверено автоматически, не человеком.
- Gate использует реальный PCM monitor default sink: stereo s16, 8000 Гц,
  RMS/peak, без ML и записи на диск. Пороги 100/1000, тишина 800 мс.
  Задержка/разрыв данных даёт UNAVAILABLE и блокирует распознавание.
  Аудиоблоки старше 400 мс не поступают в Vosk. Тишина не запускает Vosk.
- Ошибки браузера обрабатываются с закрытием принадлежащей приложению группы
  процессов. Другие окна/процессы Firefox пользователя не закрываются.

OpenAI API, ключи, внутренние API ChatGPT, чтение cookies/session tokens,
скрытого состояния страницы, координаты мыши и фиксированные Tab не используются.
Наличие `running` входного аудиопотока используется только при проверке
готовности микрофона; оно НЕ используется для определения звука динамиков.

## Фактически подтверждённый DOM

| Назначение | Наблюдавшиеся элементы |
|---|---|
| Composer | `#prompt-textarea[contenteditable="true"][role="textbox"]`, Chat with ChatGPT |
| Диктовка | Start dictation / Cancel dictation / Stop dictation / Send dictated message |
| Voice | Start Voice / Turn on microphone / Turn off microphone / End Voice |
| Отправка | `button[data-testid="send-button"]` |
| Ответ | `[data-message-author-role="assistant"]` |
| Завершение ответа | `section[data-testid^="conversation-turn-"]`, Copy response / `copy-turn-action-button`, отсутствие Stop generating, стабилизация текста |

Первоначальная SSR-оболочка показывает другой composer и Send prompt.
Автоматизация ждёт интерактивный composer; `document.readyState=complete`
недостаточно. Скрытые хранилища/React state для ожидания не читаются.

## Что прошло вживую

1. Повторное открытие постоянного профиля, авторизованный Plus, сохранённый
   доступ к физическому микрофону.
2. Открытие и завершение интерфейса Voice через DOM. Подключение Firefox
   к физическим capture-портам подтверждено PipeWire; в приложении реально
   появился `[LARISA_MODE]` при диагностическом запуске.
3. Текстовый тест: вопрос «Сколько будет два плюс два? Ответь одним словом.»
   введён через composer и отправлен через Send. Реальный ответ «Четыре.»
   получен из видимого DOM и озвучен настоящим RHVoice/pw-play.
4. Speaker gate на настоящем выходе: тишина RMS=0, речь ACTIVE (наблюдались
   RMS до 4415 и peak 9083), затем SILENT. Проверка проведена при громкости 100%.
   Пороги стартовые, не универсальная калибровка комнаты/всех уровней громкости.
5. Запуск штатной диктовки и создание входного аудиопотока Firefox.

**Сценарий A полностью не пройден:** не подтверждены голосовой ответ на живую
речь и голосовой возврат на реальном ноутбуке. Вопрос из RHVoice через динамики
не дал подтверждённого ответа; это не засчитано как разговор.

**Сценарий B частично пройден:** два живых тура с ответами RHVoice прошли;
полный hands-free acceptance с возвратом ещё не завершён.

Последующая живая проверка ANTON_MODE прошла: два последовательных вопроса
дали ответы «4» и «6», оба ответа озвучены RHVoice, после каждого ответа
запускалась новая диктовка. Основная цепочка ANTON_MODE не изменялась.

Для возврата во время активной диктовки production-путь теперь сразу отправляет
os-keyboard Space через уже установленный ARM_STOP_KEY, без snapshot/find_element/
execute_script до Stop. После этого polling ждёт `recording=False` и composer,
очищает транскрипцию без Send, затем GPTModes говорит «Слушаю». Регрессионный
тест фиксирует порядок Stop до первого snapshot.

## Устранённый блокер автоматической остановки

После старта записи обычные команды Selenium действительно зависали. Это
обходится без WebDriver click/BiDi/native Stop.

Проверены прямое DOM-нажатие и отдельный стандартный канал Selenium WebDriver
BiDi. BiDi также завершился `Timed out waiting for response to BiDi command 1`.
На странице оставался интерфейс записи, подтверждённая транскрипция не получена.
Разовая ошибка синтаксиса JavaScript в промежуточном варианте исправлена;
она отдельно НЕ засчитывается как подтверждение зависания сайта.

Для контрольного звука создавался временный узел PipeWire и добавлялись связи
только к capture-портам собственного Firefox, идентифицированного по PID.
Физический микрофон и default devices не менялись. Подавалась синтезированная
фраза, а не живая человеческая речь. Это не hands-free acceptance. Тест также
не получил транскрипцию. Временные связи/устройства подлежат удалению после теста.

Production-путь — `dictation_stop_method: os-keyboard`. Перед началом записи
`ARM_STOP_KEY` наблюдает DOM и фокусирует ровно одну видимую Stop-кнопку.
Перед Space проверяется PID активного окна и принадлежность фокуса этому
Firefox; при несоответствии клавиша не отправляется.

Ручная проверка также подтвердила саму диктовку: физический source был связан
с Firefox, живая фраза появилась в composer примерно через 0,2 секунды после
ручного Stop. Это отдельное подтверждение транскрипции, а не workaround.

```sh
.venv/bin/python dictation_probe.py --method manual
```

После ручной проверки Enter в терминале выводит состояние и закрывает только
диагностический Firefox. Сообщение в ChatGPT этот скрипт не отправляет.

## CPU/RAM — короткие измерения, не окончательный acceptance

100% CPU = одно ядро. RAM — сумма RSS дерева процессов, с повторным учётом
общих страниц; не PSS. Существующий пользовательский Firefox исключён из
дерева измерения, но конкурировал за ресурсы ноутбука.

| Измерение | Длительность | CPU | Средняя / максимальная RSS |
|---|---:|---:|---:|
| LOCAL_MODE, тихое ожидание | 15 с | 12,7% | 232,3 / 232,8 МиБ |
| Firefox + текстовый ChatGPT | 15,1 с | 26,7% | 1486,9 / 1486,9 МиБ |
| LARISA_MODE, диагностический вход, UI/микрофон активны | 15,1 с | 126,3% | 1653,0 / 1843,4 МиБ |
| Диктовка, только браузерная часть, включая проблемную остановку | 10,1 с | 85,5% | 1611,4 / 1661,9 МиБ |

Предыдущий отдельный замер полного ANTON_MODE во время записи: 15,2 с,
CPU 80,5%, RSS 1797,4 / 1837,7 МиБ, 14 процессов дерева приложения.
Эти цифры получены **до новой настройки zram и не являются финальным benchmark**. В Voice встречались переполнения очереди микрофона и задержки
монитора. Swap был занят до 511 из 511 МиБ. Надёжность на 4 ГБ RAM ещё не
подтверждена. После этих замеров добавлено пропускание тишины в Vosk GPT-режима;
его эффект не объявляется измеренным ускорением.

## Повторная проверка 15.09.2026

Подтверждена новая конфигурация: zram 1,8 ГиБ, lz4, priority 100;
/swapfile 512 МиБ, priority -1. Старые измерения выше не описывают её эффект.
Первый повторный native-тест завершился ещё на старте: после Start dictation

Firefox/geckodriver завершена отдельно; пользовательский Firefox сохранён.
Эта ручная проверка завершена успешно: фраза появилась в composer примерно
через 0,2 секунды после Stop. Затем os-keyboard Stop был подтверждён на

## Ручной Stop и отдельная проверка входа

Пользователь подтвердил ручной Stop: Firefox не завис, recording=False,
dictate=True, composer пуст, send=False, alerts пуст. Проблема автоматического
Stop рассматривается отдельно от отсутствия транскрипции.

При следующей диагностике физического source ALC3227 Analog (serial 56 в этой
сессии) получен непустой PCM: максимальные RMS в секундных окнах 14532–21833,
peak 32767/32768. ALSA Capture +30 dB, Internal Mic Boost +36 dB.
При временном снижении только Internal Mic Boost до 0 dB: RMS 147–210,
peak 445–740. Исходное значение 3,3 (+36 dB) восстановлено. Это сравнение
окружающего сигнала, не управляемая запись речи и не доказанная причина сбоя
транскрипции. Связь конкретного Firefox с этим source во время ручного теста
пока не измерена.

`dictation_probe.py` теперь выводит source/порты, реально связанные с входным
потоком собственного Firefox по PID; отличает физический capture от monitor.
Измеряет оба канала этого source без записи аудио на диск. Это уровень на
source перед обработкой в Firefox, не измерение отправленного на сервер звука.
После ручного Stop и Enter наблюдает видимый DOM 60 с: composer, остальные
видимые editors, кнопки (включая disabled), status/alert/dialog/busy/progress.
Ничего не отправляет и автоматически Stop в ручном режиме не нажимает.
Для проверки с меньшим усилением:

```sh
.venv/bin/python dictation_probe.py --method manual --internal-mic-boost 0
```

После запуска записи: две секунды тишины, короткая фраза, ручной Stop,
сразу Enter в терминале. Дождаться OBSERVATION COMPLETE и восстановления
MIC BOOST. Это необходимая следующая физическая проверка. Если транскрипция
не появится, результат не будет объявлен исправлением ANTON_MODE.

Дополнительно добавлены `dictation_audio.py`, `test_dictation_audio.py`.

После этих изменений: diff --check и py_compile чистые; 31 unit-тест прошёл,
два opt-in теста Firefox пропущены в обычном запуске (ранее отдельно проходили).
